## 1. 이 문서의 범위

상위 문서 §6 은 한 줄로 정한다 — *"로그도 권한을 받는다. `log_events` 에 `host` 가 있고, 부서별 접근 가능 호스트를 매핑한다."* §7.1 은 `query_logs`·`draft_report`·`verify_clauses` 의 시그니처를 정한다.

이 문서가 정하는 것은 **그 한 줄을 어떻게 SQL 로 번역하는가**, 그리고 상위 문서에 없는 것 하나 — **시연 화면**이다.

### 1.1 왜 시연 화면이 필요한가

현업에서 보안을 NAS 로 운영하던 사람에게 받은 피드백이 출발점이다:

> 이 프로젝트는 NAS 로 구현되는 기능이다.

**절반은 맞다.** 시놀로지에 정책 문서를 올리고 폴더 ACL 을 걸면, 권한 없는 사용자는 검색 결과에서 그 파일을 못 보고 존재조차 모른다. "권한 없는 것은 존재조차 알 수 없다" 는 파일시스템 ACL 에서 공짜로 따라온다. 새로운 주장이 아니다.

**유비가 깨지는 지점은 파생 인덱스다.** NAS 는 파일이 저장 단위이고 ACL 이 그 위에 붙는다. RAG 는 모든 등급의 청크가 **하나의 벡터 테이블**에 섞인다. 그 인덱스에는 ACL 을 붙일 자리가 없다 — 직접 만들어야 하고, 순진하게 만들면 샌다.

그러므로 이 프로젝트의 한 줄은 이렇게 된다:

> **NAS 앞에 LLM 을 세우는 순간, NAS 의 ACL 보장은 더 이상 지켜주지 않는다.**

문제는 그 사실이 지금 **테스트 파일 안에만 있다**는 것이다. 화면을 보는 사람은 "문서 검색되네" 까지만 본다. 시연 화면은 기능 추가가 아니라 **이미 한 일을 드러내는 장치**다.

### 1.2 무엇을 하지 않는가

- 문서 업로드 UI·대화 히스토리·OCR 등 표면적을 넓히는 기능. NAS 지적을 그대로 다시 받는다.
- 로그 이상탐지 모델. 상위 문서 결정 11 — 조회·인용까지가 P0.
- 전역 정확한 집계 엔드포인트. 화면이 자기가 아는 만큼만 주장하게 하는 것으로 족하다.

## 2. 로그에는 문서에 없던 문제가 있다

### 2.1 개수가 답이 된다

문서 검색은 상위 k개를 돌려준다. k 가 고정이므로 **개수가 등급에 따라 달라지지 않는다.** W2 의 핵심이 이것이었다.

로그는 다르다. "어젯밤 인증 실패 몇 건인가" 의 답은 **개수 자체**이고, 상위 k개로 자를 수 없다. 김개발은 12, 최임원은 47을 받는다.

**이것은 누출이 아니다.** 각자 자기 권한 안에서 정확한 답을 받았고, 김개발이 47을 알 방법은 없다. 문서 검색과 같다.

### 2.2 위험은 반대 방향이다

에이전트가 자연어로 답한다 — *"어젯밤 인증 실패가 12건 있었습니다."* 이것은 세상에 대한 절대적 주장으로 읽힌다. 보안 담당자가 이 문장을 읽고 대응을 종료하면, 실제로는 35건을 놓친 채 상황이 닫힌다.

**누출보다 이쪽이 실무에서 더 위험하다.** 누출은 공격자에게 정보를 주지만, 부분 집계를 전체로 오해하는 것은 방어자를 직접 무력화한다.

### 2.3 무조건적 고지는 통로가 아니다

답을 범위 안에 가둔다 — *"당신이 볼 수 있는 호스트에서 인증 실패 12건."*

여기서 반론이 나온다: 그 문장이 "네가 못 보는 호스트가 있다" 를 알리는 것 아닌가? 문서 쪽에서는 정확히 그 이유로 "권한이 없습니다" 대신 "찾지 못했습니다" 를 쓴다.

**이 문장은 안전하다. 조건 없이 항상 나오기 때문이다.**

숨겨진 이벤트가 1000건이든 0건이든 문구가 같다. 전 호스트를 볼 수 있는 최임원에게도 같은 문장이 나간다. **값에 따라 변하지 않는 고지는 통로가 아니다.** 누출 통로는 관측값이 숨은 데이터의 유무에 따라 *변할* 때 생긴다.

문서 규칙과 모순이 아니라 같은 규칙의 다른 적용이다:

| | 문서 | 로그 |
|---|---|---|
| 관측되는 값 | 결과 k개 (고정) | 이벤트 개수 (가변) |
| 위험 | 개수 차이로 존재 노출 | 부분 집계를 전체로 오해 |
| 장치 | 사전 필터링 + 고정 k | 사전 필터링 + **무조건적 범위 고지** |
| 검증 | 등급별 개수가 같다 | **고지 문구가 등급과 무관하게 동일하다** |

마지막 칸이 테스트가 된다. 세 페르소나의 응답에서 범위 고지 문구가 **문자열로 동일한지** 단언한다. 등급에 따라 문구가 갈리는 순간 그것이 통로다.

### 2.4 고지를 모델에 맡기지 않는다

모델이 문장에 고지를 넣어주기를 바라지 않는다. 모델은 잊는다.

`query_logs` 가 **호출되었다는 사실**을 API 응답이 별도 필드로 싣고, 화면이 무조건 렌더한다. 문구는 상수이고 페르소나에 따라 변하지 않는다. `policy.enforce` 가 모델을 믿는 대신 예외를 던지는 것과 같은 자리다.

## 3. 호스트 권한

### 3.1 규칙을 복사하지 않고 재사용한다

```sql
CREATE TABLE hosts (
    name                TEXT PRIMARY KEY,   -- log_events.host 와 같은 문자열
    department          TEXT NOT NULL,
    required_clearance  INT  NOT NULL DEFAULT 1,
    allowed_departments TEXT[]              -- NULL = 전사 공개
);
```

`documents` 와 **같은 두 권한 컬럼**이므로 `core/access/visibility.py` 를 그대로 쓴다. 새 판정 함수를 쓰지 않는다.

이것이 중요한 이유: 문서 쪽에서 같은 규칙이 이미 SQL·파이썬·TypeScript 세 벌로 늘어났고, 최종 리뷰가 글자 단위로 대조해서 일치를 확인했다. 로그가 자기 규칙을 새로 쓰면 **네 벌째**가 된다. 컬럼 이름을 맞춰 함수 하나로 둔다.

`allowed_departments` 가 배열인 이유는 공유 호스트가 실재하기 때문이다 — VPN 게이트웨이처럼 전사가 보는 장비는 빈 배열(전사 공개)이 된다.

### 3.2 등록되지 않은 호스트는 JOIN 으로 닫는다

`log_events.host` 는 파싱된 자유 문자열이다. `hosts` 에 없는 호스트의 이벤트를 어떻게 다루는가.

- 전원 공개로 취급 → **열리는 방향으로 실패.** 채택하지 않는다.
- 아무도 못 봄 → 안전하지만 이벤트가 조용히 사라진다.

**층을 나눠 둘 다 쓴다.** 적재 시점에 `hosts` 에 없는 호스트를 **거부한다** — 시끄럽게, 제때. 조회 시점에는 `hosts` 로 **INNER JOIN** 한다.

INNER JOIN 을 고른 이유가 핵심이다. `WHERE` 절은 빼먹을 수 있지만 **JOIN 을 빼먹으면 권한 컬럼이 없어 쿼리가 아예 성립하지 않는다.** 권한 행이 없으면 이벤트 행도 없다 — 검사가 아니라 구조로 보장된다. 나중에 `hosts` 행을 지워도 열리지 않는다.

### 3.3 권한의 기준은 호스트이지 로그 줄 안의 이름이 아니다

내가 볼 수 있는 서버에 최임원이 로그인한 기록은 **보인다.** 이것은 결정이지 누락이 아니다.

근거: 호스트는 권한이 걸린 자원이고, 그 자원에서 일어난 일은 그 자원을 볼 수 있는 사람의 소관이다. 로그 줄에 등장하는 이름으로 권한을 다시 자르면 (a) 규칙이 두 축이 되어 SQL 로 번역되지 않고, (b) 상위 문서 결정 2 — *권한 모델을 단순하게 유지, SQL WHERE 로 번역되지 않으면 애플리케이션 레이어로 밀려나고 그 순간 사후 필터링이 된다* — 와 정면으로 충돌한다.

## 4. 도구

### 4.1 `query_logs`

```python
query_logs(event_type: str | None, since: str | None, limit: int,
           runtime: ToolRuntime[AgentContext]) -> list[LogEvent]
```

`principal` 은 `search_policy` 와 같이 `ToolRuntime` 뒤에 숨는다 — `tool_call_schema` 에 나오지 않으므로 모델은 그 인자의 존재를 모른다. `limit` 에 상한을 둔다.

`raw`(원본 로그 줄)는 모델에 넘긴다. 분석가에게 필요한 증거이고 이미 호스트로 걸러진 뒤다. 원본 보존은 상위 문서 §10 의 방침이기도 하다.

### 4.2 조항 매핑 표를 만들지 않는다

"이 인증 실패가 어느 조항 위반인가" 에 답하는 자연스러운 유혹은 `event_type → 조항 코드` 매핑 테이블이다. `auth_failure` → `2.5.3`.

**만들지 않는다.** 어떤 이벤트 유형이 어느 조항에 걸리는지는 보안 담당자의 판단이고, **그 추측을 테이블에 굳혀 정답처럼 내놓는 것**은 W3b 에서 처리 상태 컬럼과 티켓 번호를 뺀 근거와 정면으로 충돌한다. 저장하는 곳이 없는 값을 화면에 두지 않는다는 규칙은, 근거 없는 값을 테이블에 두지 않는다는 규칙과 같은 것이다.

대신 에이전트가 한다. `query_logs` 로 이벤트를 받고 거기서 만든 질의로 `search_policy` 를 부른다. 도구가 둘인 이유가 이것이고, 호출 상한 8회가 "규정 검색 → 로그 조회 → 재검색 → 리포트" 두 바퀴를 상정한 값이다(상위 §7.2).

모델이 조항 번호를 지어내는 문제는 **`verify_clauses` 가 잡는다.** 조항 코드는 `clauses` 테이블에 있거나 없거나 둘 중 하나라 판단이 필요 없다 — 상위 문서 결정 6.

차이는 이것이다. 표에서 나온 매핑은 **사실인 척한다.** 모델이 고른 조항은 **모델의 추론이고, 그 인용이 실재하는지는 프로그램이 검증한다.**

### 4.3 로그 코퍼스

합성하되 **형식은 진짜다** — sshd/syslog 형식이므로 파서는 실물을 파싱한다. 문서 코퍼스의 "본문은 진짜, 등급은 합성" 과 같은 구조이고, 합성이라는 사실을 화면에 밝힌다(상위 §10 리스크 표).

**코퍼스가 판별력을 갖도록 심는다.** W2 에서 픽스처 규모가 부족해 뮤테이션이 잡히지 않은 사건이 있었으므로(`jekyll/verification.markdown` 항목 ②), 처음부터 이렇게 심는다:

> **권한 밖 호스트의 이벤트를 가장 최근 것으로 심는다.**

그러면 `query_logs(limit=10)` 에서 낮은 등급 주체는 **오래된 허용 이벤트 10건**을 받아야 한다. 사후 필터링으로 짜면 — 최근 10건을 뽑고 나서 거르면 — **2건만 받고 나머지 8건이 조용히 사라진다.**

문서 쪽 개수 테스트의 로그판이며, 잡아내는 것이 "존재 노출" 만이 아니라 **"권한 있는 데이터가 잘려나가는 것"** 이라는 점에서 더 낫다. 후자는 방어자에게 직접적인 피해다.

## 5. 시연: 데모 전용 누출 경로

### 5.1 두 단계의 누출

**1단계 — 교과서적 순진함.** 전체 청크에서 상위 k개를 뽑고 **그다음에** 권한으로 거른다. 최임원 10건, 김개발 6건. 누구나 즉시 본다. RAG 를 처음 쓰는 사람이 자연스럽게 쓰는 코드가 이것이다.

**2단계 — 고쳤다고 믿은 뒤에도 남는 것.** 사전 필터링을 넣어도 플래너가 CTE 를 인라인하면 HNSW 근사 검색이 후보를 잘라 다시 샌다. 눈으로 볼 수 없고 `EXPLAIN ANALYZE` 로 CTE 행 수를 봐야 잡힌다.

**시연 화면은 1단계를 실행하고, 2단계가 존재한다는 것을 말한다.**

> 1단계는 "이렇게 짜면 샌다" 를 보여준다. 2단계는 **"고친 줄 알았는데 여전히 샜다"** 를 보여준다. 두 번째가 이 프로젝트가 실제로 한 일이고, 테스트 없이는 알 수 없다는 증거다.

현재 코퍼스(338청크)에서 1단계는 확실히 보인다. 2단계는 이 규모에서 **재현되지 않는다** — 문서당 300개면 안 나오고 2,000개여야 0건이 된다는 실측이 `tests/test_leakage.py` 에 상수와 주석으로 기록돼 있다. 그러므로 2단계는 라이브로 돌리지 않고 **측정 기록을 출처와 함께 인용한다.**

### 5.2 격리

`backend/demo/` 를 새 최상위 패키지로 둔다. `core/`·`adapters/`·`api/`·`pipeline/`·`eval/` 의 형제다.

격리는 **세 방향 전부** 테스트로 강제한다:

| 규칙 | 강제 방법 |
|---|---|
| `core/` 가 `demo` 를 import 하지 않는다 | `test_boundaries.py` 의 `바깥_계층` 에 `"demo"` 추가 |
| `adapters/`·`pipeline/`·`eval/` 도 마찬가지 | 새 테스트 — 이 디렉터리의 어떤 파일도 `demo` 를 import 하지 않는다 |
| **`api/` 안에서 `demo` 를 import 하는 파일은 정확히 하나** | `api/*.py` 를 훑어 `demo` 를 import 하는 모듈 집합이 `{api/demo.py}` 와 **정확히 같은지** 단언 |

마지막 줄이 핵심이다. 부분집합이 아니라 **정확히 같은지**를 본다. `main.py` 가 언젠가 편의상 `demo` 를 끌어다 쓰면 그 순간 테스트가 터진다.

파일 자체도 오해할 수 없게 만든다 — `demo/naive_search.py` 의 독스트링 첫 줄이 *"이 경로는 의도적으로 샌다. 프로덕션에서 호출되면 안 된다."* 이다.

### 5.3 이 경로가 돌려주는 것

**조항 코드와 개수만. 본문은 없다.**

누출을 보여주는 데 본문이 필요 없다. 필요한 것은 개수가 갈리는 것과 순위가 갈리는 것이고, 조항 코드면 둘 다 보인다. 시연을 위해서라도 본문이 이 경로로 나가지 않는다는 불변식은 깨지 않는다.

### 5.4 비용

**모델을 부르지 않는다.** 임베딩 한 번(로컬 모델) 뒤에 검색 6번(사전·사후 × 페르소나 3)이다. LLM 호출이 0이므로 하루 상한에 걸 필요가 없고, 몇 번을 돌리든 요금이 0원이다.

### 5.5 무엇을 주장하는가

"세 계정 모두 정확히 같은 개수를 받는다" 는 **무조건 참이 아니다.** 각 페르소나의 허용 문서에서 뽑을 수 있는 청크가 k개 이상일 때만 같다(최종 리뷰 지적). 화면은 이렇게 주장한다:

> 사전 필터링에서는 개수가 **권한 범위의 크기가 아니라 k 에 의해** 정해진다.
> 사후 필터링에서는 개수가 **권한 범위의 크기를 그대로 드러낸다.**

조건 없이 참이고, 화면에서 실제로 벌어지는 일과 일치한다.

---

## 6. 동작 원리 화면

패널 넷. **각 패널은 무엇이 뒷받침하는지를 자기 안에 갖는다.**

| 패널 | 내용 | 뒷받침 |
|---|---|---|
| ① 같은 질문, 세 페르소나 | 사전 필터링에서 개수가 k 로 고정. "순진한 방식으로 다시" 토글 → 개수가 갈라짐 | **지금 실행됨** |
| ② 고친 줄 알았는데 여전히 샜다 | CTE 인라인 → 근사 인덱스 후보 절단. 문서당 300개에서는 재현 안 되고 2,000개여야 0건 | **측정 기록.** 라이브 아님을 화면이 명시 |
| ③ 기록이 담지 않는 것 | `access_records` 에 본문도 제목도 없음. 제목만으로 존재가 드러남 | **스키마 + 컬럼 추가 시 실패하는 테스트 둘** |
| ④ 같은 불변식, 두 데이터 타입 | 문서는 고정 k 로, 로그는 무조건적 범위 고지로 | **양쪽 누출 테스트** |

**규칙: 이 화면에 뒷받침 없는 문장을 한 줄도 넣지 않는다.** 라이브면 라이브라고, 인용이면 어디서 왔는지를 화면이 스스로 밝힌다. 그러지 않으면 처리 상태 컬럼을 뺀 이유를 이 화면이 배신한다.

## 7. 결정 기록

상위 문서 §11 을 잇는다.

12. **로그 권한은 호스트로 정한다** — 로그 줄 안의 이름으로 자르면 규칙이 두 축이 되어 SQL 로 번역되지 않고, 그 순간 사후 필터링이 된다 (3.3)
13. **`hosts` 는 `documents` 와 같은 권한 컬럼을 쓴다** — 같은 규칙의 네 벌째 사본을 만들지 않기 위해 `visibility.py` 를 재사용한다 (3.1)
14. **등록되지 않은 호스트는 INNER JOIN 으로 닫는다** — `WHERE` 는 빼먹을 수 있지만 JOIN 은 빼먹으면 쿼리가 성립하지 않는다 (3.2)
15. **조항 매핑 표를 만들지 않는다** — 근거 없는 매핑을 테이블에 굳히면 사실인 척한다. 모델이 고르고 `verify_clauses` 가 실재를 검증한다 (4.2)
16. **범위 고지는 모델이 아니라 응답 필드가 싣는다** — 모델은 잊는다. 문구가 조건 없이 상수이므로 통로가 아니다 (2.3, 2.4)
17. **데모 전용 누출 경로를 실제로 만든다** — 시연이 말이 아니라 실행이어야 한다. `api/` 안에서 그것을 import 하는 파일이 정확히 하나인지 테스트가 강제한다 (5.2)
18. **데모 경로도 본문을 돌려주지 않는다** — 누출을 보여주는 데 본문이 필요 없다 (5.3)
