# W5 배포 계획 — 터널 · 무료 · 포트폴리오

**Goal:** secu-agent 를 `whoareryu.cloud` 에 올린다. 프론트는 Vercel(항상
켜짐), 백엔드와 DB 는 이 맥의 도커에서 Cloudflare Tunnel 로 노출한다.
**전부 무료 범위 안에서 한다.** 기존 새싹은 서브도메인으로 옮겨 살린다.

**상위 Spec:** `docs/superpowers/specs/2026-09-01-w3-deployment-design.md` §2.
**이 계획이 그 §2 를 두 군데 뒤집는다** — 아래 결정 1·2.

---

## 결정과 그 대가

### 결정 1 — Cloudflare Containers 도 Neon 도 쓰지 않는다

W3 스펙은 백엔드를 Cloudflare Container 에, DB 를 Neon 에 두기로 했다.
그 구성은 Workers Paid $5/월을 전제한다.

**이 프로젝트는 포트폴리오이고 무료 범위 안에서만 간다.** 그리고 이미
필요한 것이 다 있다 — 이 맥에서 `whoareryu-cloudflared` 가 돌고 있고,
`secu-agent-backend-1` 과 `secu-agent-db-1`(pgvector pg16)이 나란히 떠 있다.
터널에 라우트를 하나 더 얹으면 그대로 공개된다.

얻는 것:
- **$0.** Tunnel 무료 · Vercel Hobby 무료 · 도커 로컬 무료.
- **DB 가 영속이다.** 도커 볼륨(`secuagent_pgdata`)이라 열람 기록이 살아남는다.
  Cloudflare Container 였다면 잠들 때마다 사라졌을 것이다.
- **로컬과 배포가 같은 Postgres 다.** `AS MATERIALIZED` 인라인 여부는 플래너
  거동이고 `test_leakage.py` 가 그것을 실측한다. 같은 이미지를 쓰면 그 실측이
  배포에서도 그대로 유효하다.
- 3GB 이미지를 레지스트리에 올릴 일이 없다.

### 결정 2 — 24시간 가동하지 않는다. 그 사실을 화면이 말한다

맥이 꺼지면 백엔드가 죽는다. 필요할 때만 켜두는 운용이다.

**대가를 감추지 않는다.** 백엔드가 없을 때 화면이 일반 오류를 뱉으면
포트폴리오로서 최악이다 — 만든 사람이 관리하지 않는 사이트처럼 보인다.
대신 **왜 꺼져 있는지를 화면이 말한다.** 이 프로젝트는 뒷받침 없는 문장을
금지하는 규율을 이미 갖고 있고, "지금 라이브가 아니다" 를 밝히는 장치
(`EvidencePanel` 의 evidence 배지, `로그_범위_고지`)도 이미 있다. 같은 방식을
쓴다.

**꺼져 있어도 `/how` 의 패널 ②③④ 는 그대로 동작한다.** 셋 다 `measured`·
`schema` 라 백엔드를 부르지 않는다. 즉 이 프로젝트의 논증 대부분은 백엔드가
꺼져 있어도 읽힌다 — 라이브인 패널 ① 만 비활성이 된다. 그 사실이 우연이
아니라 설계의 결과라는 것을 화면이 말할 수 있다.

### 결정 3 — 새싹의 터널 라우트 넷은 손대지 않는다

`api` · `n8n` · `auth` · `ssh` 는 전부 새싹 것이다. secu-agent 는 **새 호스트명**
(`secu-api.whoareryu.cloud`)을 받는다. 바뀌는 것은 새싹 **프론트엔드의
주소**뿐이다(apex → `saessak.`).

### 결정 4 — DNS 는 Cloudflare 에서만 만진다

`dig NS whoareryu.cloud` → `leonidas/miki.ns.cloudflare.com`. 네임서버가
Cloudflare 로 위임돼 있으므로 **가비아 DNS 관리 화면의 레코드는 효력이 없다.**
거기 남아 있는 두 줄은 이전 설정의 잔재다. 가비아는 등록기관 역할만 한다.

## Global Constraints

- 커밋 메시지는 한국어, 평서형 과거.
- 시크릿을 이미지에 굽지 않는다.
- `NEXT_PUBLIC_` 로 백엔드 주소·시크릿을 내보내지 않는다.
- 새싹의 기존 터널 라우트 넷을 건드리지 않는다.
- **새싹의 새 주소가 뜨는 것을 확인한 뒤에 apex 를 옮긴다.**

## 국면 A — 저장소 (내가 한다)

### Task 1: secu-agent 백엔드를 터널 네트워크에 붙인다 — 완료

`docker-compose.tunnel.yml`(신규)이 백엔드를 `cloudwhoareryu_app-network`
에도 참여시킨다. 로컬 개발이 깨지지 않도록 별도 파일로 뒀다 — 그 네트워크가
없는 환경에서 `docker-compose.yml` 만으로도 떠야 한다.

**여기서 남의 서비스를 반쯤 끊는 사고가 났다.** Compose 는 **서비스 이름을
네트워크 별칭으로 자동 추가**하고 그것을 끌 방법이 없다. 두 스택의 서비스
이름이 똑같이 `backend` 였으므로, 같은 네트워크에 붙는 순간 그 이름이 두 IP
로 풀렸다. 터널의 `http://backend:8000`(새싹 API)이 8000 을 듣지 않는
secu-agent 백엔드로 절반씩 갔다.

**고침:** `docker-compose.yml` 의 서비스 이름을 `secu-backend` 로 바꿨다.
별칭을 지울 수 없으니 이름을 고유하게 만들어 충돌을 구조적으로 없앤다.
그 이유를 파일 주석에 실측과 함께 적어뒀다 — 짧게 되돌리고 싶어지는 이름이라
왜 안 되는지가 그 자리에 있어야 한다.

확인: 공유 네트워크에서 `backend` 별칭은 `whoareryu-backend` 단독,
secu-agent 는 `secu-backend`. 새싹 API 6회 연속 307,
`localhost:18080/healthz` 가 `{"status":"ok","db":true,"model":"ready"}`.

### Task 2: 백엔드가 꺼져 있을 때의 화면

`/api/healthz` 가 이미 있다. 그것으로 백엔드 상태를 확인해, 꺼져 있으면
화면이 **사실을 적는다.** 지어낸 값을 보이지 않고, 무엇이 여전히 보이는지도
말한다(`/how` 의 인용·스키마 패널).

문구는 실제 동작만 적는다. "잠시 후 다시 시도해 주세요" 같은 거짓 기대를
주지 않는다 — 켜기 전에는 다시 시도해도 안 된다.

verify: 백엔드를 내린 채 배포된 화면을 열어 확인한다.

### Task 3: 배포 문서

`README.md` 에 운용 방식을 적는다 — 상시 가동이 아니라는 것, 그것이 비용
결정이라는 것, 무엇이 꺼져 있어도 보이는지.

## 국면 B — 맥이 깨어 있게 만들기 (사람이 한다)

포트폴리오 URL 이 동작하려면 시연 시간 동안 맥이 자면 안 된다.

- [ ] **뚜껑을 닫으면 잔다.** 애플 실리콘 맥은 외장 디스플레이가 없으면
      전원이 연결돼 있어도 뚜껑을 닫는 순간 잔다. `caffeinate` 는 유휴 절전만
      막고 뚜껑 절전은 막지 못한다. **뚜껑을 열어둔다.**
- [ ] 시연 시간 동안 `caffeinate -dis` 를 띄워둔다 (디스플레이·시스템 절전 억제).
- [ ] Docker Desktop 을 로그인 시 자동 시작으로 둔다.
- [ ] 두 스택의 재시작 정책을 `unless-stopped` 로 둔다.

## 국면 D — 연결과 전환

### Task 4: 터널에 secu-agent 라우트를 더한다

Cloudflare Zero Trust → Networks → Tunnels → `whoareryu.cloud` →
Published application routes → Add:

- 호스트: `secu-api.whoareryu.cloud`
- 서비스: `http://secu-backend:8080`

새싹 라우트 넷은 그대로 둔다.

verify: `curl https://secu-api.whoareryu.cloud/healthz` 가
`{"db": true, "model": "ready"}`. 시크릿 없이 `POST /ask` 는 401.

### Task 5: 오늘 작업을 푸시한다

`origin/main` 이 아직 `32008c2` 다. Vercel 이 그 커밋을 배포해 두었으므로
`/how` 화면이 아직 없다. 푸시하면 자동 재배포된다.

### Task 6: Vercel 환경변수

`AUTH_SECRET` · `AUTH_GOOGLE_ID` · `AUTH_GOOGLE_SECRET` ·
`BACKEND_URL`(=`https://secu-api.whoareryu.cloud`) ·
`BACKEND_SHARED_SECRET` · `ADMIN_EMAILS`

verify: 프리뷰 URL 에서 로그인 → 질의 → `/how` 토글이 개수를 가른다.

### Task 7: 새싹을 서브도메인으로 옮긴다 (secu-agent 보다 **먼저**)

1. Vercel 새싹 프로젝트 → Domains → `saessak.whoareryu.cloud` 추가
2. Cloudflare DNS 에 Vercel 이 준 값으로 CNAME 추가, **프록시 끄기**
3. 새 주소가 뜨는 것을 확인
4. 새싹의 OAuth 리디렉션·절대 URL·쿠키 도메인에서 apex 를 걷어낸다
5. 그 다음에 새싹 프로젝트에서 `whoareryu.cloud` 와 `www` 를 제거

### Task 8: apex 를 secu-agent 로

1. Vercel secu-agent 프로젝트 → Domains → `whoareryu.cloud` (+ `www`)
2. Cloudflare DNS 를 Vercel 이 **그 프로젝트에** 표시하는 값으로 바꾼다.
   apex A 값은 같을 수 있지만 **`www` CNAME 은 프로젝트마다 다르다** —
   화면이 주는 값을 그대로 쓴다. 추측하지 않는다.
3. 프록시는 계속 **끄기**(회색). 지금도 apex 는 회색이다.
4. OAuth 리디렉션 URI 를 다시 확인한다.
